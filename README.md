# English Error Corrector

一个面向 DeepSeek Harness（DSH）的英文纠错 Skill。它通过固定的输出契约，把英文校对结果整理成清晰、可核对的三段式内容，而不是一段混合了说明、改写和原文的自由文本。

> 输入一段英文文本，得到：错误清单、逐条修改、修正后的完整段落。

## 1. 项目解决什么问题

直接让大模型修改英文时，常见的问题不是“改不出来”，而是结果难以核对和复用：

- **错误与修改混在一起**：错误说明、正确写法、完整改写混在同一段里，很难逐条对应。
- **分类和格式不稳定**：错误类型随意，修改理由时有时无，不同轮次的输出结构不一致。
- **多余内容干扰使用**：开场白、总结、鼓励语会稀释真正有用的批改信息。
- **容易过度改写**：为了“润色”而改变原意、语气或段落结构。

本项目把英文纠错流程固化成一个 DSH Skill，用明确的规则约束模型输出：

- 错误逐条列出，并归入“语法 / 拼写 / 搭配 / 表达”四类；
- 每条错误都有编号相同的修改项，且附一句修改理由；
- 最后单独给出修正后的完整段落；
- 只做必要修改，保留原意、语气和段落结构，不加开场白或额外总结。

它适合英语学习者、需要校对英文邮件或文章的人，以及希望获得稳定、可逐条检查的英文修改结果的用户。

## 2. 主要功能

- **按场景自动判断是否加载**：当用户提供英文文本，并要求检查、修改、校对、润色时，DSH 会根据 Skill 的 `description` 判断是否加载。支持英文请求（如 “check my English”“fix the grammar”“proofread this”）和中文请求（如“检查英文错误”“修改英文”“润色英文”）。
- **四类错误识别**：逐条列出原文中的错误，并标注为 `语法`、`拼写`、`搭配` 或 `表达`。
- **错误与修改一一对应**：修改项沿用错误项的编号和顺序，先给出修改后的片段，再用一句话说明修改原因。
- **输出完整修正结果**：第三个模块单独给出完整的修正段落，而不是只给零散片段。
- **严格的输出结构**：三个模块的标签固定，输出以 `**错误内容：**` 开始，不添加开场白、总结、鼓励语或其他解释。
- **最小化修改**：只修正明确的错误和不自然的表达，不为了风格偏好而重写全文，不添加原文没有的信息。
- **无错误时的固定兜底**：未发现错误时，依次输出 `未发现错误。`、`无需修改。` 和原文，仍然保持三个模块完整。

## 3. 安装方法

本项目本身就是一个可直接放入 DSH 技能目录的 Skill，不需要编译，也没有额外的运行时依赖。

前置条件：已安装 DSH，并启用了本地技能目录扫描；实际的英文纠错由当前 DSH 会话所使用的模型完成。

### 目录结构

```text
SKILL/
├── README.md
└── .dsh/
    └── skills/
        └── english-error-corrector/
            └── SKILL.md
```

核心文件是 `.dsh/skills/english-error-corrector/SKILL.md`，其中包含 Skill 的名称、触发描述和输出规则。

### 项目级安装

本仓库已经按项目级技能目录组织。在项目根目录下使用 DSH 时，它会扫描 `.dsh/skills/`，无需额外安装。

如果要在另一个 DSH 项目中使用，将整个 `english-error-corrector` 目录复制到目标项目的对应位置：

```text
<目标项目>/.dsh/skills/english-error-corrector/SKILL.md
```

### 用户级安装（可选）

如果希望所有项目都能使用这个 Skill，可以将目录复制到 DSH 的用户技能目录：

```text
~/.dsh/skills/english-error-corrector/SKILL.md
```

在 Windows 上，该路径通常为：

```text
%USERPROFILE%\.dsh\skills\english-error-corrector\SKILL.md
```

DSH 会监听技能目录的变化，放入或更新 Skill 后通常无需重启；新会话会按最新的技能目录加载。若技能没有出现，请确认 DSH 使用的是预期的项目根目录，并检查 `SKILL.md` 是否仍保留顶层 `name: english-error-corrector` 和合法 frontmatter。

## 4. 使用方法

直接用自然语言提出英文校对请求即可，不需要手动指定输出格式：

```text
请检查并修改这段英文：

I has went to the meeting yesterday and discuss the plan with my team.
```

也可以使用英文请求：

```text
Please proofread this paragraph and fix any grammar or collocation errors.
```

触发条件是“提供英文文本 + 要求检查、修改、校对或润色”。技能支持句子、段落、邮件和短文；多段文本会按原有段落结构处理。

模型加载 Skill 后，会按以下顺序输出：

1. **错误内容**：逐条列出错误片段和错误类型，不提前给出正确写法。
2. **错误内容修改**：按相同编号给出修改后的形式，并用一句话说明原因。
3. **修改后的完整句子**：给出完整的修正段落，不夹杂解释或批注。

如果文本没有需要修改的地方，三个模块仍然保留，内容分别为 `未发现错误。`、`无需修改。` 和原文。

> 在支持显式选择 Skill 的界面中，也可以直接选择或调用 `english-error-corrector`。

## 5. 输入输出实例

### 输入

```text
请检查并修改这段英文：

Yesterday I go to the store and buyed some apples.
```

### 输出

```markdown
**错误内容：**
1. “I go” —— 语法：Yesterday 表示过去时间，谓语未使用一般过去时。
2. “buyed” —— 语法：buy 的过去式不是通过加 -ed 构成。

**错误内容修改：**
1. “I went” —— Yesterday 表示动作发生在过去，因此将 go 改为 went。
2. “bought” —— buy 是不规则动词，因此将 buyed 改为 bought。

**修改后的完整句子：**
Yesterday I went to the store and bought some apples.
```

在这个例子中，两条错误分别对应两条修改，编号、顺序完全一致，最后给出完整的修正句子，没有额外的开场或总结。

## 适用范围与限制

- 只处理用户提供的英文文本，不用于翻译、正文生成、续写或纯内容重写。
- 纠错能力由当前 DSH 会话使用的大模型提供；本项目是行为规范，不是独立的语法检查服务或 API。
- 以修正明确错误和不自然表达为目标，不会因为个人风格偏好而大幅重写文本。
- 对合同、医学、法律等高风险文本，仍建议由专业人员复核。
